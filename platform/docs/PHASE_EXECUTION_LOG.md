# سجل تنفيذ البناء — الحازم سمارت v10 workstream

## قواعد الحفظ
- هذه النسخة مبنية على نسخة العمل v9.1؛ لم تُحذف ملفات أو مسارات قائمة عمدًا.
- لا تُنفذ تغييرات مدمرة على قاعدة البيانات ولا حذف بيانات.
- المرجع الحاكم: وثيقة الحازم سمارت الإصدار 1.0 بتاريخ 17 أكتوبر 2026.
- حالة «أُنشئ المسار» لا تعني أن الوظيفة مكتملة؛ كل قسم جديد يوضح متطلبات استكماله.

## المرحلة 1 — الفحص وتثبيت المرجع
**الحالة: أُنجزت مراجعة المصدر المتاح، ويستمر التحقق الآلي.**
- تم حصر صفحات التطبيق وواجهات API وترحيلات قاعدة البيانات والوثائق في حزمة v9.1.
- تم الحفاظ على ملفات المشروع الأصلية داخل نسخة العمل الجديدة.
- أُضيف فاحص `npm run verify:reference` للتحقق من وجود مسارات أساسية وترحيلات المرجع وترتيب AUX قبل Footer.

## المرحلة 2 — قاعدة البيانات والأمان
**الحالة: جزئي؛ لا يمكن اعتمادها نهائيًا دون Supabase staging.**
- احتُفظ بتعديلات الأمان السابقة في migration 005.
- حدود الطلبات الحالية داخل العملية الواحدة فقط؛ لا تعد محددًا مشتركًا للإنتاج.
- لم تُطبق migrations على قاعدة بيانات حية ولم تختبر RLS بحسابات منفصلة.
- لم تُجر تغييرات مخطط إضافية في هذه الدفعة لتجنب افتراض بنية غير متحققة.

## المرحلة 3 — طبقة البيانات والهوية المركزية
**الحالة: جزئي.**
- أُضيف `lib/config/site.ts` كمصدر مركزي لبيانات الهوية والاتصال.
- عُدلت الصفحة الرئيسية ودليل العلامات لاستخدام بيانات الاتصال المركزية.
- قيم الاتصال الافتراضية تطابق الوثيقة المرجعية: الهاتف 01050509779 وواتساب 01044111143.
- يجب على المالك تأكيد القيم قبل الإنتاج، خصوصًا إذا طرأ تغيير بعد تاريخ الوثيقة.

## المرحلة 4 — جودة المحتوى
**الحالة: أساس تنظيمي فقط.**
- تمت إضافة صفحات/مسارات واضحة للأخبار والنصائح والأكاديمية والشفافية والعروض وAUX والتكييف والمطبخ والإضاءة والأسئلة الشائعة والمجتمع ونادي الحازم والدعم والملف الشخصي.
- هذه الصفحات لا تعرض محتوى أو أسعارًا تجريبية؛ توضح المتطلبات التي يجب استيفاؤها قبل التفعيل.
- لم تتم إضافة كتالوجات شركات أو صور منتجات غير موثقة.

## المرحلة 5 — الوظائف الذكية
**الحالة: لم يبدأ استكمال الوظائف الذكية المتقدمة.**
- المسارات الحالية للمستشار والمقارنة محفوظة.
- لا يوجد بعد RAG موثق أو استرجاع مصادر منتجية شامل يضمن اقتصار كل جواب على سجل موثوق.

## المرحلة 6 — تجربة الاستخدام
**الحالة: جزئي.**
- أضيفت روابط الأقسام المرجعية للصفحة الرئيسية.
- وضع قسم AUX مباشرة قبل Footer كما تنص الوثيقة.
- أضيفت صفحة 404 فعلية وملفا robots وsitemap.
- أضيف مسار مستقل لحاسبة قدرة التكييف، لكنه لا يقدم نتائج رقمية قبل اعتماد معادلة هندسية ومراجعتها.

## المرحلة 7 — الاختبار
**الحالة: فحص مرجعي محدود ناجح؛ فحوص TypeScript والبناء والتكامل لم تثبت بعد.**
- نجح `node scripts/verify-reference.mjs` في فحص المسارات الأساسية والاتصال وترتيب AUX.
- نجح فحص الصياغة عبر TypeScript 5.8.3 لعدد 69 ملفًا دون أخطاء صياغة.
- انتهى `npm install` بمهلة؛ لذلك لم تتوفر أنواع Next.js/React/Supabase.
- فشل `npm run lint` بسبب غياب الاعتماديات والأنواع، وليس دليلًا كافيًا على أخطاء TypeScript منطقية في المشروع.
- لم يثبت `npm run build` بسبب عدم اكتمال تثبيت الاعتماديات.
- يلزم اختبار RLS والرفع وAuth وAI والطلبات في staging.

## المرحلة 8 — الإطلاق
**الحالة: لم يبدأ.**
- لا يوجد نشر إنتاجي من هذه الدفعة.
- لا تُعد المنصة جاهزة للإطلاق قبل إغلاق P0/P1 واختبارات القبول وتأكيد الإعدادات والبيانات.

## الخطوة التالية الملزمة
1. تثبيت الاعتماديات وإنشاء lockfile من بيئة موثوقة.
2. تشغيل TypeScript والبناء وإصلاح الأخطاء الفعلية.
3. مراجعة مخطط Supabase وكتابة migrations غير مدمرة عند الحاجة.
4. بناء إدارة المحتوى والأسعار والمصادر وحالات التحقق.
5. استكمال صفحات العلامات والمنتجات والبحث والمستشار والـ CRM وفق المرجع.
6. اختبار القبول الكامل ثم الإطلاق.
