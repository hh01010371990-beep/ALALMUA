# منصة الحازم — مجموعة العالمية (V9)

هذه النسخة (V9) تطور الصفحة المرجعية الحالية على أساس Next.js/TypeScript، مع بنية قابلة للتوسع إلى:
- Product Master + Seller Offers
- Multi-vendor marketplace
- Supabase Auth + PostgreSQL + RLS
- AI Workforce
- Smart Comparison
- Virtual Home / 3D / AR
- Admin Command Center

## التشغيل

1. انسخ `.env.example` إلى `.env.local`.
2. ضع مفاتيح Supabase.
3. ضع `OPENAI_API_KEY` عند تفعيل المستشار الذكي الحقيقي.
4. نفّذ ملفات `database/migrations` بالترتيب 001 ثم 002 ثم 003 ثم 004، وبعدها ملف `database/seeds/001_reference.sql` داخل مشروع Supabase.
5. نفّذ:
   `npm install`
   `npm run dev`

## ملاحظة مهمة

المشروع يتضمن أساساً تنفيذياً واضحاً، لكن مفاتيح الخدمات الخارجية، حساب Supabase، بيانات المنتجات الحقيقية، نماذج 3D/AR، بيانات المنتجات الحقيقية ونماذج 3D/AR تحتاج إدخالها قبل الإطلاق. تم إعداد أرقام التواصل المقدمة من الشركة: اتصال 01044111143، واتساب 01050509779، والعنوان محافظة كفر الشيخ، مدينة سيدي غازي، أمام موقف الميكروباص. لا يوجد شراء أو سلة أو دفع داخل المنصة؛ يسجل العميل طلب تواصل ويتولى موظف المبيعات إتمام البيع خارج المنصة.

## المحتوى المرجعي

تم الحفاظ على هوية الصفحة الأصلية: RTL، الكحلي والذهبي، دليل العلامات، مقارنة التكييف، رفايع المطبخ، الإرشادات، ونموذج الطلب، ثم تحويلها إلى أساس قابل للتوسع.


## بوابة التجار

- الصفحة العامة: `/merchant`
- نموذج طلب الانضمام: `/merchant/apply`
- واجهة API لإرسال الطلب: `POST /api/merchant/apply` (تتطلب مستخدمًا مسجل الدخول).
- Migration إضافية: `database/migrations/002_merchant_portal.sql` بعد `001_core.sql`.

طلبات التجار تُحفظ بحالة `PENDING`، ولا يستطيع مقدم الطلب اعتماد حسابه بنفسه. يجب تطبيق migrations وضبط متغيرات Supabase واختبار سياسات RLS قبل تشغيل البوابة على بيانات حقيقية. لوحة مراجعة الإدارة وإدارة عروض التجار متاحة كأساس؛ متابعة العميل المهتم تتم من قائمة المبيعات، ولا يوجد نظام طلبات شراء داخل المنصة.

### مراجعة واعتماد التجار (تحديث التطوير)

- لوحة مراجعة طلبات التجار داخل `/admin`، بعد تسجيل الدخول بحساب إداري مسموح.
- لوحة التاجر `/seller` تعرض حالة الحساب، وبعد الاعتماد تتيح إنشاء/تحديث عرض على منتج موجود وإدارة السعر والمخزون والضمان والتوصيل.
- `GET /api/admin/merchants` لعرض الطلبات والحالات.
- `PATCH /api/admin/merchants/[id]/review` لتغيير الحالة إلى قيد المراجعة أو معتمد أو مرفوض أو موقوف مع ملاحظة مراجعة.
- `GET /api/seller/overview` لتحميل حالة التاجر والمنتجات والعروض الخاصة به.
- `POST /api/seller/offers` لحفظ عرض على منتج موجود؛ يتطلب حساب تاجر معتمدًا.
- محرر ملف المتجر في `/seller` لتعديل الاسم والوصف وبيانات التواصل والعنوان وسياسات التوصيل والاسترجاع.
- `GET /api/seller/store` و`PUT /api/seller/store` لقراءة وحفظ ملف المتجر بعد اعتماد الحساب.
- يضيف تحديث migration `002_merchant_portal.sql` حقول ملف المتجر وفهرسًا يمنع إنشاء أكثر من متجر للتاجر نفسه.
- يسجل تحديث حالة التاجر في `audit_logs` عند تطبيق migration `002_merchant_portal.sql`.
- صلاحيات الواجهة البرمجية تُفحص على الخادم، وسياسات RLS تظل طبقة الحماية الأساسية في قاعدة البيانات.
- لم يُختبر هذا التحديث على مشروع Supabase حي؛ يجب تطبيق migrations في بيئة اختبار، وتجربة حساب غير إداري وحساب إداري، والتحقق من سجلات التدقيق قبل الإنتاج.


### حدود النسخة الحالية

تعديل ملف المتجر لا يفعّل ظهوره تلقائيًا؛ التفعيل من صلاحيات الإدارة. رفع الصور الفعلي عبر Supabase Storage، وتم حذف مسارات السلة وإتمام الشراء والطلبات والعمولات لأنها خارج نطاق المنصة. يعتمد المسار المعتمد على تحويل اهتمام العميل إلى قائمة متابعة المبيعات. لم يتم تأكيد نجاح `npm run build` أو اختبار سياسات RLS على مشروع Supabase حي في هذه البيئة.


## مسار المبيعات والقوة العاملة الافتراضية
- لا توجد سلة شراء أو صفحة إتمام شراء أو بوابة دفع أو سجل طلبات شراء.
- من بطاقة المنتج يرسل العميل طلب تواصل يتضمن الاسم والهاتف والمنتج والملاحظات؛ يُحفظ في `sales_leads` بعد تهيئة Supabase.
- فريق المبيعات المصرح له يتابع الطلبات من `/admin/sales-leads` ويتواصل مع العميل خارج المنصة لإتمام البيع.
- Migration `003_sales_handoff_ai_workforce.sql` تنشئ قائمة العملاء المحتملين وتجهّز عشرة موظفين افتراضيين متخصصين.
- واجهة المساعد `/api/ai` تدعم اختيار موظف افتراضي؛ يلزم `OPENAI_API_KEY` للإجابات الفعلية.
- قبل الإطلاق: طبّق migrations بالترتيب 001 ثم 002 ثم 003 ثم 004، واضبط صلاحيات RLS واختبرها في مشروع Supabase تجريبي.


### تحديث متابعة المبيعات
- يستطيع فريق المبيعات تحديث حالة العميل من `/admin/sales-leads` إلى جديد، تم التعيين، تم التواصل، عميل مهتم، تمت المتابعة، أو تعذر الوصول.
- يتم تحديث الحالة من خلال API يتحقق من دور المستخدم، ثم دالة PostgreSQL `update_sales_lead_status` تتحقق مرة أخرى من الصلاحية.
- تمنع قاعدة البيانات التعديل المباشر على صفوف العملاء من خلال صلاحيات العميل؛ يجب تطبيق migration 003 كاملة حتى يعمل تحديث الحالة.
- تم توضيح موافقة استخدام بيانات الاتصال داخل نموذج العميل.

### حدود واضحة للنطاق
لا تشمل المنصة سلة شراء أو checkout أو دفعًا إلكترونيًا أو فواتير شراء أو عمولات أو تسويات مالية. المنصة تعرض المعلومات وتساعد على المقارنة، وعند رغبة العميل في الشراء يرسل طلب تواصل، ثم يتولى موظف المبيعات إتمام البيع خارج المنصة.


### إدارة الموظفين الافتراضيين
- صفحة الإدارة: `/admin/ai-workforce`، متاحة للأدوار الإدارية المصرح بها.
- يمكن تعديل اسم الموظف الافتراضي وتعليماته أو إيقافه مؤقتًا؛ لا توجد صلاحيات تلقائية لتعديل الأسعار أو نشر المنتجات أو تنفيذ معاملات.
- عند تهيئة Supabase، يقرأ مساعد `/api/ai` تعليمات الموظف النشط من جدول `ai_agents`؛ أما الإجابات الفعلية فتحتاج `OPENAI_API_KEY`.
- تضبط migration 003 سياسات قراءة الموظفين النشطين وإدارة سجلاتهم من قبل الأدوار الإدارية المحددة.

- أضيف رابط مباشر لأداة المقارنة في الصفحة الرئيسية، وتم تعديل `npm run lint` ليشغّل فحص TypeScript بدل أمر `next lint` غير الملائم في بعض إصدارات Next.js 15.

### الإصدار V9 — لوحة الكتالوج والتواصل الرسمي
- صفحة إدارة الكتالوج `/admin/catalog` متاحة للأدوار الإدارية فقط، وتتيح إضافة وتعديل وحذف المنتجات، وإدارة الوصف والموديل وSKU والأبعاد واستهلاك الكهرباء والضمان والمواصفات الإضافية وحالة النشر.
- إدارة العلامات التجارية في الصفحة نفسها تتيح الاسم والوصف والموقع الرسمي وروابط الدعم والشعار وFacebook وInstagram وTikTok. الروابط يجب التحقق منها قبل النشر.
- رفع الصور يتم عبر API يتحقق من جلسة المستخدم والدور الإداري، إلى Supabase Storage في bucket `alhazem-product-media`، مع حد 5 ميجابايت وأنواع صور محددة.
- صفحة دليل العلامات `/brands` تعرض روابط المواقع الرسمية والدعم والشبكات الاجتماعية المسجلة في قاعدة البيانات.
- صفحة المنتجات `/products` أصبحت تدعم فلاتر البحث والقسم والعلامة ونطاق السعر والضمان والمواصفات، وتعرض تاريخ آخر تحديث لسعر العرض عندما يكون مسجلاً.
- Migration `004_catalog_admin_security.sql` تضيف حقول العلامات والمنتجات وسياسات RLS وbucket الصور والفهارس. المنتجات الجديدة تكون مسودات مخفية حتى ينشرها المسؤول.
- بيانات التواصل المهيأة: اتصال 01044111143، واتساب 01050509779، العنوان محافظة كفر الشيخ، مدينة سيدي غازي، أمام موقف الميكروباص.
- يلزم تطبيق migrations في مشروع Supabase تجريبي أولًا، ثم اختبار CRUD والرفع والنشر بحساب إداري وحساب غير إداري. لم يُختبر الاتصال بقاعدة بيانات حية ولم يتم النشر العام في هذه البيئة.
